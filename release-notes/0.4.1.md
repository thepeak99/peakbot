## 0.4.1

### Bug fixes

- **`/load` no longer silently keeps the boot model.** The `/load` handler was
  pre-stamping the display identity (`provider_name`, `model`, `model_alias`)
  before `maybe_rebuild_after_load` ran, making its rebuild guard vacuously
  true on every load. The agent kept its boot wire id and context window while
  the status bar showed the loaded model. Issues #3 (wrong context size), #4
  and #5 (wrong model on load) are all the same skipped rebuild. Regression
  pin added.

- **`deny_unknown_fields` on all config structs.** Misplaced or mistyped fields
  in `config.yaml` (e.g. `max_tokens` at the provider level instead of the
  model level) were silently dropped by serde. PeakBot now rejects any unknown
  field at parse time with a named-field error, making misconfiguration
  immediately visible.

- **Resumption history after mid-compaction.** After in-loop context
  compaction, the resumption handler re-derived history from
  `get_agent_history()` inside the loop body, throwing away the carefully
  built resumption tuple. The compact arm now uses a one-shot history override
  that survives the loop re-entry, preventing duplicate `ToolResult` messages
  on the wire.

- **`file_edit create` without `file_text`** now creates an empty file instead
  of failing. The `thought` tool parameter is optional; the model is coached
  to provide content on a subsequent `str_replace` call.

- **Per-model `context_size`** now takes precedence over auto-detection. A new
  `context_size` field on model entries (also accepted as `context_window` for
  backward compatibility) lets you override the detected context window.

### Internal

- **Upgraded to rig-core 0.36 + rmcp 1.6.** Fixed `&mut Vec<Message>` → `Into<Message>`
  compatibility and resolved a duplicate rmcp version conflict.
- **State machine refactor.** Replaced the ad-hoc async agent runner with a
  proper state machine backed by an async event channel.
- **552 tests passing** (401 unit + 93 integration + 58 snapshot), up from 535.
