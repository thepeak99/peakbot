# 0.3.2

Patch release. Two TUI hygiene fixes shipping the work that landed on
master after 0.3.1: a Windows-only double-keystroke bug fixed at the
dispatch boundary, and a second pass over emoji width-drift that
closes every code path the round-1 normaliser missed.

## 🐛 Bug fixes

- **Drop Windows duplicate keystrokes at the dispatch boundary
  (`bb5146d`).** Reported on Windows: every TUI keystroke registered
  twice — typing `a` produced `aa`, one Backspace deleted two cells.
  Linux/macOS were unaffected because we only push
  `DISAMBIGUATE_ESCAPE_CODES` (never `REPORT_EVENT_TYPES`), and per
  the crossterm 0.29 doc comment on `KeyEvent::kind` —
  *"Only set if: Unix: REPORT_EVENT_TYPES has been enabled; Windows:
  always"* — Windows' `ReadConsoleInputW` ALWAYS emits both Press AND
  Release records. `ReplUi::handle_input` was forwarding every
  `Event::Key(_)` to the keyboard handler without inspecting `.kind`,
  so Release records were re-running the press path.
  **Fix:** filter at the dispatch seam, not inside every key handler.
  `Event::Key(k) if k.kind == Press || k.kind == Repeat =>
  self.handle_keyboard_input(k)`, with a sibling `Event::Key(_)`
  catch-all that drops Release. Repeat is forwarded because
  autorepeat (key-hold) is genuine user intent.

- **Close kitty / Class-B emoji-width bypass paths (`c715cd8`).**
  Round 2 of the garbled-emoji fix. Round 1 normalised PlainRenderer
  + the markdown body funnel, but several bypass paths still shipped
  width-disagreement glyphs:
  - **Class A** (VS16 / ZWJ codepoints unicode-width says are narrow
    but the terminal renders wide): markdown code blocks
    (`handle_codeblock_event` builds `Span::styled` directly), the
    input area (`build_input_paragraph` splits the cursor line into
    pre/post halves), and the working title (`status_message` is
    agent-controlled). Each now normalises at its Span construction
    site. Internal literals cleaned at source: `⚙️` → `⚙`, `⚠️` → `⚠`.
  - **Class B** (`✓` / `✗`, U+2713 / U+2717 — East-Asian Narrow per
    unicode-width but kitty can render at 2 cells, drifting side-panel
    borders on scroll redraw): ASCII swap at three sites — todo_panel
    title `✓ TODO` → `+ TODO`, todo_panel cancelled icon `✗` → `x`,
    `state_manager` cancelled icon to match. Geometric-shape glyphs
    (○ ◐ ●) kept — stable across vte / kitty / Alacritty / iTerm.

## 🔧 Internals

- New module `src/ui/emoji_normalize.rs` (~250 lines incl. 17 unit
  tests). `normalize_for_terminal(&str) -> Cow<'_, str>` with a
  byte-scan fast path: ASCII / supplementary-plane emoji (e.g. 🤖,
  U+1F916) skip the slow path entirely (`Cow::Borrowed`, zero alloc).
  Slow path runs only on input containing 0xE2 or 0xEF — the leading
  bytes of every stripped codepoint.
- Stripped: ZWNJ U+200C, ZWJ U+200D, VS15 U+FE0E, VS16 U+FE0F, keycap
  combiner U+20E3. Bidi controls deliberately NOT stripped (different
  bug class, can mangle RTL).

## 🧪 Tests

- 3 new dispatch-boundary tests in `command_popup_tests`:
  `key_release_is_dropped_at_dispatch_boundary`,
  `key_repeat_is_treated_as_a_press`,
  `backspace_release_does_not_double_delete`. Without the fix, the
  first and third panicked with the user's exact symptoms reproduced
  (`left: "aa", right: "a"` and `left: "", right: "a"`).
- 17 new unit tests in `emoji_normalize`, plus 2 new code-block tests
  in `markdown.rs` (VS16 / ZWJ stripped from code blocks).
- Snapshot fallout from the round-2 fix: 5 quit_confirm + 9
  todo_panel + 1 chat_welcome (stale 0.3.0→0.3.1 version skew, swept
  as drive-by).
