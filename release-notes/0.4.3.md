# Release 0.4.3

Small patch. Two changes since 0.4.2: a new optional auth header for SearXNG, and an internal split of the file-editing tool into three focused tools.

## What's New

### feat(search): bearer_token support for SearXNG

- `searxng.bearer_token` is now an optional config field. When set, every web-search request attaches an `Authorization: Bearer <token>` header. Lets PeakBot talk to authenticated SearXNG instances behind a reverse-proxy gate without baking a token into the URL.
- Fully backward-compatible: the field defaults to `None` via `#[serde(default)]`. Existing configs need no changes.

```yaml
searxng:
  base_url: https://searx.example.com
  bearer_token: "your-secret-token"   # optional
```

## What's Changed

### refactor(tools): split file_edit into file_create / file_str_replace / file_insert

- The monolithic `file_edit` tool (one tool, three actions dispatched on a `command:` discriminator) is now **three separate tools**, each with a tight schema that only requires the fields it actually needs:
  - `file_create` — create a new file (refuses to overwrite)
  - `file_str_replace` — replace exact text in an existing file
  - `file_insert` — insert text at a specific line
- Built-in tool count: **8 → 10**.
- Model-facing benefit: schema shape makes illegal states unrepresentable. No more "I sent `command: insert` but also `file_text`" confusion — the JSON schema for each tool enumerates exactly the right fields.
- The `bash` tool's "don't use sed/awk/vim for edits" warning now points at the specific replacement tool for each disallowed command.
- Internal cleanup: the old `cmd_undo_edit` machinery and `file_history` state (~140 LOC, no readers, dead since the refactor that introduced it) are gone.
- **No config changes required.** Tool dispatch is by name; the new names are picked up automatically.
