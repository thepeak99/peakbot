# 0.4.0 — Multi-model with `/model`

Declare many models, switch between them with one command, and let
every conversation remember which model it ran on.

## What's new

### `providers:` list, `models:` per provider, aliases for typing

The new shape lets you declare every model you might want to use, give
each one a short alias, and pick which one to boot with:

```yaml
providers:
  - name: openrouter
    type: openrouter
    api_key: sk-or-v1-xxx
    models:
      - name: anthropic/claude-3.7-sonnet
        alias: sonnet
      - name: anthropic/claude-opus-4
        alias: opus
  - name: openai
    type: openai
    api_key: sk-xxx
    models:
      - name: gpt-4o
        alias: oai-gpt4

default_model: sonnet
```

Aliases are short, lowercase, mnemonic — pattern `^[a-z0-9_-]+$`. When
you don't pass an `alias` the wire `name` is used directly. Per-model
overrides (`max_tokens`, `temperature`, `num_ctx`, `extra_params`,
`context_window_override`) all behave like the legacy single-provider
shape.

The legacy `provider:` block still works unchanged — it's promoted on
load to a one-entry registry with alias `default`.

### `/model` command

- **`/model`** — lists every alias with the active one marked `→`.
- **`/model <alias>`** — switches and starts a fresh conversation. If
  the current chat has content, you get a Ctrl+C-style confirmation
  overlay first.
- **`/model <unknown>`** — fails with `❌ /model: unknown alias …
  Available: …`. No state change.
- **`/model <current>`** — `Already on X.` No destructive reset.

The switch happens **between turns** — if the agent is mid-prompt your
`/model` request waits its turn. MCP server subprocesses survive the
switch (only the agent handle is rebuilt), so any long-running
external tools keep their state.

### Conversations remember their model

Every conversation now carries `model_alias` in its metadata.
`/load <id>` re-activates the saved alias; if that alias is no longer
in your config (renamed, removed, or pre-v4 file), the load is
rejected with `❌ Model 'xyz' not available.` and your current
conversation stays intact. No silent guesses, no half-loaded state.

`/conversations` shows the model column and dims rows whose alias is
no longer available. Pre-v4 files appear as `(pre-v4) ⚠ unavailable`.

### Reusable confirm dialog

The Ctrl+C quit overlay was generalised into a typed `ConfirmDialog +
ConfirmAction` enum so `/model` could share it without duplicating the
chrome. Future confirm-gated commands plug in by adding a
`ConfirmAction::Foo` variant — grep-able, matchable, no closure
trickery.

## Behaviour notes

- **Mid-conversation switching is intentionally not supported.** Each
  conversation is single-model by construction. `/model` ends the
  current convo and starts a fresh one — your old convo is persisted
  and reachable via `/load <n>`.
- **`unknown` is a reserved alias** — used internally for pre-v4
  conversation files. Declaring `alias: unknown` in your config is a
  startup error.
- **/stop and /model can't race.** /stop targets the active prompt's
  hook through a shared cell; after a /model swap the cell points at
  the new agent, so /stop always cancels the *current* prompt and
  never a stale predecessor.
