# Release 0.4.2

Bug-fix patch. The three commits shipping today fix a compact-mode boot regression introduced during the multi-model refactor, and two pre-existing compaction reliability issues that could cause the agent to hang silently.

## What's Fixed

### fix(compact): bail loudly on compaction failure; refuse to boot with broken compaction config

- **Layer 2 — Runtime escape hatch:** When `force_compact()` cannot produce a summary mid-turn (e.g. no OpenRouter API key), the turn now aborts with a clear `❌ Compaction failed` system message and returns an error to the model instead of looping silently. Previous behavior swallowed the error, cleared stale state, and re-armed the same fallback — producing the "RSS bloat + 100% CPU" hang pattern that triggered the original investigation.

- **Layer 1 — Boot gate:** PeakBot now refuses to start when `context.enabled=true` and the compaction model cannot be constructed (missing API key). Previously the error was silently discarded (`ok().map(Arc::new)`), leaving compaction permanently broken with no signal to the user.

### fix(boot): mirror resolved provider into config.provider so multi-model compaction config boots

- **Multi-model boot regression (regression):** In multi-provider configs, `config.provider` held its `default()` values (no API key) while the resolved provider lived only in the registry. The compaction-model constructor read `config.provider` and saw no credentials. The `/model` switch path was already mirroring correctly; boot was not. Fixed by extracting `Config::resolve_and_mirror_boot_provider`, a helper that returns the resolved value *and* writes it back into `self.provider` as a side effect, keeping the legacy-field consumers consistent.

- The error message for Layer 1 failures now names the active provider instead of misleadingly pointing at `context.enabled`.

### chore: remove release debug profile setting

- Removes the `[profile.release] debug = true` added during the hang investigation. Release builds are back to optimised.
