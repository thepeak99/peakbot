# 0.3.1

Patch release. Two correctness fixes shipping the work that landed on
master after 0.3.0: the single-writer queue refactor that makes
mid-tool user input structurally safe, and a pair of TTY-hygiene fixes
that stop tests (and panics) from stranding the developer's terminal.

## 🐛 Bug fixes

- **Single-writer queue for user input (`bb6e8ba`).** The
  `add_user_message{,_with_attachments}` call moved out of `event_loop`
  (where it could splice user-text *between* an in-flight `ToolCall`
  and its `ToolResult`) into `agent_loop`, which is the only task that
  runs *between* turns. Mid-tool user input is now structurally
  impossible to corrupt rig history. Typing during a busy turn becomes
  a queued *follow-up* (no longer an interrupt); `Esc` / `/stop` drain
  the queue via a shared `Arc<AtomicBool>` flag.

- **Mouse-capture leak in tests (`43df346`).** `toggle_select_mode`
  (the F4 binding) used to unconditionally `execute!(stdout(),
  Enable/DisableMouseCapture)`. Under `cargo test` the harness
  builds `ReplUi` via `::new` *without* `init()`, so those bytes
  leaked onto the developer's live tty — leaving mouse-reporting
  stuck on and spamming the prompt with `35;43;18M`-style sequences
  on every cursor move until they ran `reset`. Fix: gate the IO on
  `self.terminal.is_some()` (the existing real-terminal predicate).

- **Drop guard for ReplUi (`43df346`).** New `impl Drop for ReplUi`
  emits the same teardown sequence as `shutdown()` (`disable_raw_mode`
  + `PopKeyboardEnhancementFlags` + `LeaveAlternateScreen` +
  `DisableMouseCapture`, in reverse-of-init order, errors swallowed)
  whenever `self.terminal.is_some()`. A panic mid-render or an `?`
  short-circuit before `shutdown()` runs no longer strands the
  terminal in raw mode + alt screen + mouse capture.

## ✨ UX

- **Queued-message hint moved into the working title (`f4f2c45`).**
  When messages are queued during a busy turn, the count surfaces as
  `⏳ N queued` *inside* the working spinner title
  (`" ⠋ Working · 00:07 · thinking · ⏳ 3 queued · esc to stop "`)
  rather than down in the status bar. The eye is already on the
  spinner during a busy turn; the status bar isn't where you look.

## 🧪 Tests

- New regression pin
  `f4_does_not_emit_mouse_escapes_without_a_terminal` asserts the
  unattached-terminal precondition + state flips correctly + cancels
  out across two presses.
- New regression pin `drop_without_init_is_a_safe_noop` asserts Drop
  is a no-op + non-panicking on test-built `ReplUi` (the attached
  branch is four `let _ = ...` lines verified by inspection — emitting
  `DisableMouseCapture` to real stdout from a test would graffiti the
  developer's tty, which is precisely the leak under guard).
- New behavioural pin
  `queued_messages_are_sent_as_separate_turns_not_glued`: three
  back-to-back `run_message` calls produce exactly 3 LLM requests,
  each carrying its own one-line prompt. Defence-in-depth assertions
  catch space-joined / newline-joined / run-on shapes if the equality
  ever loosens.
- New `StateManager` mutator unit tests for `pending_input_count`
  (increment / decrement / set / saturating-floor at 0).
- 4 new integration tests in `queued_input_tests.rs` covering
  user-precedes-assistant ordering, multi-turn alternation, tool-event
  call-then-result ordering, and pending-input lifecycle.
- 2 new working-title pin tests
  (`working_title_shows_queued_count_when_pending_and_busy`,
  `working_title_omits_queued_segment_when_count_is_zero`).
- 5 compaction tests recalibrated (`keep_recent: 2 → 3`) — the new
  `add_user_message` ordering shifts compaction one turn earlier under
  the previous setup; behaviour is identical, threshold just moved.

## 🔧 Internals

- `QueueMessage::UserMessage` is now a struct carrying `text +
  attachments` (was a bare string).
- `AppState::pending_input_count: usize` (`#[serde(default)]` for
  backward compat with on-disk conversation JSON).
- `build_input_paragraph` takes a new `pending_input: usize` arg
  (mechanical fan-out across ~13 call sites).
- TestRunner ordering aligned to mirror production
  (`add_user_message` BEFORE `prompt`).
