# 0.2.1

Patch release. Ships the post-0.2.0 deadlock fix in the binary and
introduces a version-controlled release-notes pipeline so future
releases stop relying on one-shot PATCH backfills.

## 🐛 Fixes

- **`sync_stats_to_ui` deadlock removed.** The helper used to hold
  `stats.lock` across `state.write`, inverting the order taken by
  `sync_to_conversation` (`state.read` → `current_conversation` →
  `stats`). Cross those two on the multi-threaded runtime and the
  agent loop's `add_assistant_message → persist_current` deadlocks
  against the event-processor's `add_request`, so `/new` → first
  prompt → first response on a fresh session would hang. Fix:
  snapshot stats fields under the lock, drop the guard, then take
  `state.write`. Pinned by
  `add_request_and_persist_current_do_not_deadlock`, a two-producer
  regression test with a pure-atomic watchdog (~500ms with the fix,
  hangs without).

  *Note:* this fix was attributed to the 0.2.0 backfilled notes, but
  landed in master after the 0.2.0 binaries were already built and
  published. 0.2.1 is the first published binary that contains it.

## ✨ Pipeline

- **Release notes are now version-controlled.** Drop a markdown file
  at `release-notes/<v>.md` before running `make release` and its
  contents become both the annotated tag message and the Gitea
  release body. Resolution order: `NOTES=<path>` CLI override →
  `release-notes/<v>.md` → literal `Release <v>` fallback (pipeline
  never blocks). Read via `jq --rawfile`, so backticks, quotes, `$`,
  and emoji are all safe. See `agents.md` § *Release pipeline →
  Release notes* for the full walkthrough.
