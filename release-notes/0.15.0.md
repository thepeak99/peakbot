## Changes

- Pipeline overhaul phase 1 (lane plumbing, latent — no behaviour change yet): added `MessageSource::SubAgent { role }` and an `is_orchestrator_lane()` predicate. `get_agent_history` now filters to the orchestrator lane, so a sub-agent's turns will never leak into the orchestrator's wire context (Background turns still counted as orchestrator input). Renderer and web UI label sub-agent turns with a `🧩 <role>` badge; the REPL render-cache fingerprint now includes the message source lane.
- Pipeline overhaul phase 2 (config): a `pipeline:` role now references a `model:` **alias** from the top-level `providers:` list (the same aliases `/model` uses) instead of re-declaring provider/credentials. The role shape is now `{ model?, prompt, env? }` — dropped the per-role `type`/`api_key`/`base_url`/`max_tokens`/`temperature` fields (model, key, base URL, and max-tokens come from the resolved alias). An omitted `model:` falls back to `default_model`. Roles are resolved and validated at boot: an unknown alias, empty prompt, or empty role name is now a clear startup error instead of a silent misconfiguration. The optional per-role `env:` (mirrors `bash.env`) is plumbed through, to be merged into the sub-agent's bash tool in a later phase. Removed a dead duplicate `src/pipeline/config.rs`.
- Pipeline overhaul phase 3 (event lane tag + cost roll-up, latent — no behaviour change yet): agent events now travel the internal channel wrapped in a `SourcedEvent` that carries the lane (`MessageSource`) that produced them. A `SessionHook` stamps its own lane (defaulting to the orchestrator), so a sub-agent's hook can tag its `ToolCall`/`ToolResult`/`CompletionResponse` events with its role. The event consumer stamps that lane onto the resulting transcript message (so the renderer can label a sub-agent's turns) and rolls a sub-agent's tokens and cost into the parent session `/stats` regardless of lane — a delegation's cost can no longer be silent.
- Pipeline overhaul phase 4 (delegate rebuild — the phase that makes sub-agents live): the `delegate` tool is now `delegate(role, task)` and runs **one** sub-agent to completion, returning a single result string — dropped the old `mode`/`timeout`/`series`/`parallel` surface, so delegations are structurally sequential. A delegated sub-agent now receives the **full built-in toolset** (minus `delegate` itself — no nested delegation) built through the same path as the orchestrator, gets the role's `env:` merged into its bash tool, runs with its own fresh context, and TEEs its turns to the shared transcript tagged with the role while its tokens/cost roll into `/stats`. Hitting **stop** during a delegation now cancels the running sub-agent as well as the orchestrator — the whole turn unwinds. (Note: a role configured on an Ollama model is hookless by design, so its turns aren't TEE'd, cost-tracked, or stop-cancellable — matching Ollama's existing no-cost-tracking behaviour.)
- Pipeline overhaul phase 5 (docs, example, and an integration test — no behaviour change): documented the orchestrator + sub-agent model in `agents.md` (the isolation invariant, lane/colour labelling, the sequential guarantee, cost roll-up, the config shape, and the v1 "no harness sandbox" note), and added a `delegate` row to the tools table (registered only when `pipeline.enabled`). Rewrote the `examples/pipeline-team/` config and README to the current role shape — the old example used the pre-overhaul `type`/`api_key`/`entrypoint` fields and an `orchestrator` *role* that no longer exists (the orchestrator is your top-level `default_model` agent), so it would have been rejected at load. Added a consumer-level integration test asserting that one delegation TEEs the sub-agent's turns into the transcript, keeps them out of the orchestrator's wire history, surfaces the returned string as the orchestrator's tool result, and rolls the sub-agent's cost into `/stats` — all through the real public seams.
- Pipeline overhaul phase 6 (persistence + isolation fixes so sub-agent work survives reload and stops bleeding into the orchestrator's surfaces):
  - **Message lane is now persisted (A):** the on-disk `conversation::Message` gained a `source` field, so reloading a past conversation keeps each message on its original lane instead of resurrecting everything as `Human`. Sub-agent (`🧩 <role>`) and Background (`🛰`) turns now render correctly after `/load`. The field defaults to `Human` and is omitted from JSON for human turns, so existing conversation files are unaffected.
  - **Sub-agent prose is surfaced on its lane (B):** a sub-agent's assistant/reasoning **text** (not just its tool calls) now enters the transcript tagged with its role, live and persisted — previously it died in the delegate's throwaway history and was invisible.
  - **Sub-agents get an isolated todo list (C):** the `todo` tool given to a sub-agent is now backed by its own in-memory list instead of hard-erroring `StateManager not set`. The orchestrator's todo panel is untouched by a sub-agent's todos.
  - **Sub-agent shell output no longer bleeds into the orchestrator's bash panel (D):** a sub-agent's `bash` tool runs PTY-backed against the session cwd but is no longer wired to the live bash panel, so the operator's panel only reflects the orchestrator's own commands.
  - **`/stats` now breaks down usage per lane (F):** session statistics accumulate a per-lane bucket (tokens, requests, cost), and `/stats` prints an orchestrator-vs-sub-agent breakdown so heavy delegation is visible rather than blended into one total.
  - **Conversations carry a `pipeline_enabled` marker (G):** a conversation-global boolean recording whether the multi-agent pipeline was enabled for the session that created it, stamped at creation and exposed on `ConversationSummary`. Defaults to `false` for every pre-existing file. (The web picker badge is a deferred frontend concern.)
- Web UI: added an **"Agents"** side-panel tab (Phase 1, clickable dummy — frontend only, no backend). An "Enable subagents" checkbox reveals a selectable list (Global · Orchestrator · sub-agent roles); selecting an entry re-scopes the transcript in place via each message's existing `source` lane (Global = all with badges, Orchestrator = non-sub-agent turns, a role = that role's turns), with a "Watching &lt;role&gt;" banner + empty state. Roster is a hardcoded placeholder pending later phases.
- Web UI: Agents tab Phase 2 — the sub-agent roster is now **derived live from the transcript** (the `source.role` values seen) instead of a hardcoded placeholder, so roles appear as soon as they take a turn and vanish when a conversation without them is loaded. Each role shows a turn-count badge, the "dummy" tag is gone, and an empty state ("No subagents yet") shows when no sub-agent has spoken. The Agents tab handle carries a roster-size badge when watching is enabled. Still frontend-only — zero backend changes.
- Web UI: Agents tab Phase 3 — per-lane stats and an honest pipeline status.
  - The **Session panel now scopes to the watched view**: selecting a sub-agent role (or Orchestrator) in the Agents tab re-scopes the token/call/cost rows to that lane's usage, with a "scoped to &lt;role&gt;" banner; Global keeps the grand totals. The per-lane breakdown that already powered the TUI `/stats` is now carried on the web `AppState` wire (`SessionState.lanes`). The context-usage meter stays session-wide (it's not a per-lane fact).
  - The Agents panel shows a **truthful pipeline-status line** driven by the real backend `pipeline_enabled` flag (now mirrored onto the live `AppState`): "Pipeline active — sub-agents available" when configured, otherwise a note to add a `pipeline:` block to config.yaml and restart. (This phase left the checkbox as a local show/hide; the follow-up below ties it to the backend flag.)
- Web UI: Agents tab fixes — the panel now tells the truth and scopes every side panel to the watched agent.
  - The **"Enable subagents" checkbox now reflects the real backend `pipeline_enabled` state** instead of a misleading local toggle. When the session's pipeline is active the checkbox is **checked and grayed out** (you can't switch a boot-only capability off from the UI); when it's not configured it's unchecked and grayed, with the existing "add a `pipeline:` block and restart" note. This fixes the confusing state where a conversation that clearly had sub-agents still showed the checkbox unchecked and toggleable.
  - **Selecting an agent now scopes the Files, Todo and Session panels to that lane**, not just the transcript. The Files panel shows only the files that agent touched (derived from its slice of the transcript — e.g. the PM's PRD vs. the developer's code skeleton); the Session panel scopes tokens/calls/cost to the lane; and the Todo panel shows the orchestrator's list (sub-agents run ephemeral, un-surfaced todo lists, so a sub-agent view shows an honest "not surfaced" note instead of the orchestrator's todos).
  - **Per-lane stats now persist across reload**: the per-lane token/call/cost breakdown is saved into the conversation metadata and restored on `/load`, so a resumed pipeline conversation can scope the Session panel to a sub-agent instead of reading zeros. The field defaults to empty, so pre-existing conversation files are unaffected (their per-lane data was never recorded and can't be reconstructed).
- Web UI: **lane-labeled global todos + per-delegation Agents roster** (two follow-up fixes to the lane-scoped panels).
  - **Global todos now show every lane's list, each labeled by the agent it belongs to.** Previously the global Todo panel replayed the whole mixed transcript in one pass, which blended the orchestrator's and every sub-agent's lists together (and corrupted ids, since each lane has its own independent backend `TodoList` with its own id space and `clear`-resets). The global view now replays **per lane** — orchestrator first, then each delegation in call order — and tags each item with a small lane pill ("Orchestrator", a role, or "role · call N"). A scoped view (a specific agent/call) still shows just that lane's list, **unlabeled**, exactly as before.
  - **Repeated delegations to the same role no longer collapse into one label.** When the orchestrator delegates to the same role several times, the Agents panel now lists **one row per delegation** in call order (suffixed `#n` only when a role ran more than once), each independently selectable so you can watch just that one delegation's turns/todos/files. Delegations are sequential and non-nested, so per-call identity is derived purely from transcript position — **no backend change, and it works on already-saved conversations.** A per-call view rolls its stats up to the role's lane bucket (per-message tokens aren't on the wire — honest degradation). Zero Rust, zero protocol change; the Files tab intentionally stays global-mixed.
