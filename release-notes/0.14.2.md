# Release Notes (Working Draft)

This file is the working draft for the next release. When a version is tagged, this file is renamed to `<version>.md` and a new empty `current.md` is created.

## Changes

- **`peakbot --web --tls` — HTTPS with a built-in CA (batteries included).** PeakBot now self-signs a local certificate authority on first use (stored in the OS cache dir, private key `0600`) and mints a fresh leaf every boot whose SANs follow this machine's addresses (loopback + LAN IP + concrete bind IP). Install the CA on your phone once — over the tokenless `/peakbot-ca.crt` endpoint (correct `application/x-x509-ca-cert` MIME, so phones offer to install it directly) — and get a trusted padlock from then on. Enable via the `--tls` flag or `web.tls: true` in config. Pure rustls/aws-lc-rs + rcgen — no OpenSSL, so the cross-builds stay clean. On boot PeakBot prints the HTTPS URL, the CA-install URL (using the LAN IP), the iOS trust-settings hint, and the CA path.
- **`--tls` leaf now covers the machine's mDNS `<hostname>.local` name automatically**, and a new repeatable **`--tls-name <NAME>`** flag adds arbitrary extra DNS names or IPs to the certificate. The `.local` name survives DHCP IP changes, so a phone bookmarked at `https://mymachine.local:7823` keeps its padlock even when the LAN IP shuffles. Extra names *augment* the auto SANs (loopback, LAN IP, `.local`) — they never replace them.
- Fixed the web UI notification bell doing nothing on mobile: mobile browsers reject the `new Notification()` constructor (`Illegal constructor`), so pings were silently swallowed even though the bell lit up and permission was granted. PeakBot now registers a notification-only service worker and fires task-completion notifications via `ServiceWorkerRegistration.showNotification()`, falling back to the constructor on desktop. The service worker has no `fetch` handler — it does not cache assets or turn the app into a PWA.
- The notification bell now explains itself on insecure connections. Browsers hard-gate both notification permission and service workers to secure contexts (HTTPS or `localhost`), so a phone reaching PeakBot over a plain-HTTP LAN address can never enable notifications — previously the bell just showed a misleading "blocked in browser settings" tooltip. It now detects the insecure origin and says so: "Notifications need HTTPS or localhost — this connection is insecure." Serve over HTTPS or use a tunnel/port-forward to enable notifications on mobile.
