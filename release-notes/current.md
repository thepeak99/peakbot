# Release Notes (Working Draft)

This file is the working draft for the next release. When a version is tagged, this file is renamed to `<version>.md` and a new empty `current.md` is created.

## Changes

- **CI:** Bring up Gitea Actions on the repo. New `.gitea/workflows/ci.yml` runs `cargo fmt --check`, `cargo clippy --all-targets --locked -- -D warnings`, and `cargo test --workspace --locked` on every PR against `master`, using the in-tree `rust:1.95` image on the `dind` runner. Pure-git checkout (no `actions/checkout` dependency, no `node` in the container). Three `test_connect_mcp_server_*` tests now carry `#[ignore]` — they spawn `uvx` to fetch an MCP server from GitHub and need network + Python the CI image doesn't provide; they continue to run locally via `cargo test -- --ignored`. New "CI (Gitea Actions)" section in `agents.md` documents the gate, the Gitea API quirks (job-id lookup, `?run=` filter being ignored), and a polling snippet for new runs.

- **Refactor (#11, slice 1):** Extracted shared PTY-spawning core into new `src/pty_runner.rs` module — `LineBuffer`, `PtyStatus`, `PtyHandle`, `spawn`, `strip_ansi`, `truncate_line`. `bg_processes.rs` now delegates spawn ceremony, reader thread, and kill to `pty_runner`, keeping only registry-level concerns (multi-process map, two-tier circuit breaker, drain semantics). Zero behaviour change — sets up shared use by the upcoming `bash` PTY port and live-output panel.
- **Feature (#11, slice 2):** UI scaffolding for the foreground `bash` tool panel. New `BashPanelState` enum on `AppState` (`Idle` / `Running` / `Finished`) with four `StateManager` setters (`start_bash_panel`, `update_bash_panel_tail`, `finish_bash_panel`, `clear_bash_panel`) and a new `src/ui/repl/bash_panel.rs` renderer (bottom-strip layout, 5-line scrolling tail, header glyph + pid/exit + elapsed/duration, inline `stdin» _` row when Running). Panel is hidden when `Idle` and lives between chat and input when active. No producer wiring yet — slice 3 ports the foreground `bash` tool to `pty_runner` and starts feeding this state. 5 snapshot tests pin the visual contract for each lifecycle state.
- **Feature (#11, slice 3):** Foreground `bash` tool is now PTY-backed via `pty_runner`. Every command runs under a real pseudo-terminal, so `isatty()`-checking programs (`ls --color=auto`, `sudo`, `ssh` host-key prompts, `git push` credential prompts) behave normally. Live output is mirrored to the slice-2 bash panel as it streams (200ms debounce; panel transitions `Idle → Running → Finished` automatically). **Behaviour change:** the tool result now uses a single `OUTPUT:` block (PTY merges stdout/stderr into one stream) instead of separate `STDOUT:` / `STDERR:` sections. The cardinal "one buffer, two views" invariant is pinned by a new integration test — every byte the panel saw also appears in the tool result. Commands that block reading stdin (e.g. bare `cat`) now sit until `timeout_seconds` elapses; the tool description and tests document the "pipe input in" recipe.
- **Feature (#11, slice 4):** Type into a live `bash` child. While the foreground bash panel is `Running`, **Ctrl+S** focuses the inline stdin row; characters typed there land in a buffer rendered with a block cursor. **Enter** forwards the line (plus `\n`) to the PTY master so prompts from `sudo`, `ssh`, `git`, `read`, and any other interactive command finally have somewhere to receive input. **Esc** unfocuses and preserves the buffer (recovery contract — never silently drop typed bytes; matters most for passwords). Focus auto-resets when the panel leaves `Running` (child exited, `/new`, `/load`, `/model`). Echo suppression is the PTY's job: `read -s` and `sudo` set `termios ECHO off` and the bytes never bleed into the output buffer — pinned by the `bash_stdin_no_echo_suppressed_under_pty` integration test. New `StateManager::try_forward_bash_stdin(line) -> Result<(), StdinNotActive>` makes the recovery contract self-documenting in the type. **+16 tests** (4 sidecar + 6 REPL state + 3 integration + 2 snapshot + 1 predicate).

- **Closes #11 (slice 5):** Final pin + scope close-out. New snapshot test `bash_panel_running_long_line_clips_at_right_edge` locks the v1 long-line contract — the panel **clips at the right edge** rather than wrapping (a deliberate divergence from the plan's "wrap and consume tail rows" — wrapping would make the tail footprint variable; clipping keeps the 5-row strip stable). The snapshot exists so any future "let me turn on `Wrap { trim: false }`" change must explicitly bless the diff. Ticket #11 closed with a scope-reduction comment documenting what shipped (PTY, live panel, stdin forwarding, credential prompts) and what is intentionally out of scope (full-screen TUI apps: `vim`, `htop`, `less`, `nano`, `git rebase -i` — those belong in the user's own terminal, not embedded inside an agent).

- **Feature (UX):** **Close the foreground bash panel with `Ctrl+B`.** Toggles a view-only `bash_panel_hidden` flag on `AppState` — orthogonal to the `BashPanelState` machine (the producer keeps streaming under the hood; only the renderer changes draw behaviour). Works regardless of whether the panel is `Running` (live tail) or `Finished` (last frame). Hidden auto-reverts at the start of every new user prompt (single chokepoint: `StateManager::add_user_message` + `_with_attachments`; bg synthetic turns deliberately do not reset). Layout treats `hidden ≡ Idle`, so the chunk collapses to zero rows and chat reclaims the real estate. Title hint `· Ctrl+B to hide` shown in both Running and Finished frames for discoverability. **Esc deliberately not used** — it routes to the agent-interrupt catch-all, so an Esc-based dismiss would have stolen the agent-stop keystroke whenever the panel was visible. New pin `esc_still_interrupts_agent_with_finished_panel_visible` guards against the regression; the design and Zen review live in `close-bash-panel-v2.md`. **+14 tests** (5 state-manager + 1 renderer wiring + 6 keybind + 2 snapshot).
