# Release Notes (Working Draft)

This file is the working draft for the next release. When a version is tagged, this file is renamed to `<version>.md` and a new empty `current.md` is created.

## Changes

- **Every tool call now has a wall-clock budget.** A session wedged for over an hour inside `fetch_page` on a host with an invalid TLS cert: the `spider` crate uses its own HTTP client, so PeakBot's `http:` timeouts never applied, and nothing between that await and the top of the process armed a deadline — a sub-agent lost 150+ completed tool calls. Every tool the model can call (built-in and MCP, gated or not) is now wrapped in a deadline at the single registration seam: 30 min by default, 2 h 5 min for `bash`/`powershell` (above their own `timeout_seconds` clamp), and the delegation budget + 5 min for `delegate`. An expired call comes back as a normal tool result (`⏱ TIMEOUT: tool …`) the model can react to, not a killed turn, and is logged at `error` level. On top of that, `fetch_page` bounds each fetch attempt at 35 s and reports the URL that never answered (a hung attempt is terminal — a host that swallows the request will not answer 3 s later), and a delegation is bounded at 1 h after which the sub-agent's transcript is still summarised back to the orchestrator as an `INTERRUPTED` handoff instead of being discarded. Fast tools are unaffected — the wrapper is a pass-through. Design: `docs/tool-time-budget-design.md`.
- **Time budgets are configurable.** A new `timeouts:` block sets both ceilings — `tool_secs` (default 1800, i.e. 30 min) and `delegate_secs` (default 3600, i.e. 1 h), each `1..=86400` seconds; `0` is rejected rather than meaning "disabled". The block is reload-safe: edit it and the next `/new`, `/model`, `/cd`, or `/load` picks it up. The shell and delegate budgets stay derived from those two numbers so the ordering that makes each tool's own message win cannot be inverted by hand.
- **`http.read_timeout_secs` now defaults to 1800 (was 600).** For non-streaming completions that value is effectively a ceiling on a single generation, and 10 minutes cut off models that legitimately think longer. The `http:` block is still boot-only — but editing it and then running a session verb now warns `⚠ http change ignored — restart to apply.` instead of silently doing nothing.
- **Compaction in sub-agent conversations**: The compaction gate now reads only the orchestrator lane's last request size, so a sub-agent's large internal turn no longer triggers premature compaction. This also prevents the summary from being wedged between a tool call and its result after compacting, which could cause the provider to reject the conversation.
