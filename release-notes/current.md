# Release Notes (Working Draft)

This file is the working draft for the next release. When a version is tagged, this file is renamed to `<version>.md` and a new empty `current.md` is created.

## Changes

- Stop is now two-stage: the first press finishes the running tool call and then stops; press Stop (or Esc) again to stop immediately.
- ruvector-core upgraded to 2.4.0 — default HNSW index no longer uses hnsw_rs (no upfront capacity reservation), redb connection-pool lock-race fixes; existing vector DBs open unchanged.
- Vector store: no longer pre-reserves ~35 GiB per open (hnsw_rs 0.3.5 fix + HNSW capacity hint capped at 100k), which could crash PeakBot during doc_index/doc_search.
- Dev tooling: `make clean` now removes ALL build artifacts — root and desktop cargo targets, `web/dist` + `web/node_modules`, the desktop sidecar binaries, `gen/` and fetched emoji fonts, `output/`, and `.release-version` — while restoring the tracked `.gitkeep` placeholders.
- CI: a new `desktop` job checks the full desktop workspace (core + Tauri glue) with fmt/clippy/test on every PR, so the Tauri glue crate is no longer untested between desktop.yml release builds.
- Web UI: new **Focus mode** toggle (top bar, on by default). Hides tool calls, tool results, background turns and other intermediate steps, showing only your messages, the final answer of each turn, and any errors. While the agent works, a single live activity line shows the latest step. Preference is remembered per browser.
- PeakBot Desktop: new Settings window (tray "Settings…", macOS menu `PeakBot → Settings…`, Ctrl+Shift+S / Cmd+Shift+S, or the link on the status page) to choose HTTP/HTTPS, access-token on/off, and remote access; saving restarts the session (or reinstalls the background service) after a confirm dialog. Remote access forces HTTPS and the token — the token is now only mandatory for remote access; on loopback you can turn it off (any local page can then drive PeakBot, see #378). The Settings page now **shows the access token and lets you replace it**: type your own (letters, digits, `-`, `_`, `.`; 16–256 characters — this applies to loopback too), press **Generate** for a random one, **Copy** it, or leave the field empty to keep the current token (or generate one). The new token is written to `web-token` (mode `0600`) and never to `settings.json`, the service unit or the command line. On **Linux** the app window now **trusts PeakBot's own certificate automatically** in HTTPS mode — only when it is presented by PeakBot's own backend on this computer and cryptographically signed by the CA in `~/.cache/peakbot/tls/ca-cert.pem`; anything else still gets the normal certificate error page. On **macOS** the window shows a certificate warning until the certificate is trusted (deferred). Settings persist in `settings.json` in the app's data folder — delete it to reset. The session now reuses the persistent `~/.config/peakbot/web-token` instead of minting a new token on every launch (a terminal `peakbot` will therefore start using it too).
- `peakbot service install` accepts `--tls` and repeatable `--tls-name <NAME>`: the service artifact (systemd unit / launchd plist / Windows task) runs the agent over HTTPS with the built-in CA, and `service status` reports the state as a new `TLS: on` / `TLS: off` line derived from the installed artifact.
- Windows: `peakbot install` no longer fails with "Access is denied (os error 5)". The install copy now opens the destination with a single write handle (copy + chmod + `sync_all` on it); Windows `FlushFileBuffers` requires write access, so the old read-only reopen failed.
- Windows: `peakbot service install` now works over SSH. The Task Scheduler user is resolved with `whoami` (falling back to `USERNAME` + `COMPUTERNAME`), because under Windows OpenSSH the `USERDOMAIN` environment variable is `WORKGROUP`, which `schtasks` cannot map to an account.
- PeakBot Desktop: on start, the app now checks whether the installed background service is **exactly** the PeakBot build it bundles, by comparing file contents, not just the version number. If the builds differ, it replaces the service and `~/.local/bin/peakbot` automatically, with no dialog, keeping the service's HTTP/HTTPS mode and access token. Previously a service with the same version number but an older build kept running unnoticed. If the installed PeakBot is *newer* than the app's, the app still asks first ("Keep" is remembered). If the binary can't be written, the existing service is left running and the app shows the error.
- Groundwork for the new config layout: a new config parser with path-precise errors, and automatic migration of old configs (global and per-repo) that keeps the original file as `config.yaml.pre-0.24`. Not active yet — nothing changes for users in this release.
- PeakBot Desktop for Windows now ships as a **single portable exe** (`PeakBot-Desktop-<v>-windows-x86_64.exe`) — no installer, no VC++ runtime required. On first launch it unpacks its bundled PeakBot backend to `%LOCALAPPDATA%\com.peakbot.desktop\bin\` and runs it from there; deleting the exe and the data folders removes it completely. Background mode is not yet available on Windows.
- CI: the `desktop` job now also runs the Windows portable-exe pipeline's static tests (build-script/Dockerfile/Makefile contract checks plus the in-container smoke checks unit-tested against fake executables) on every PR, so the Windows build pipeline can't silently drift.
- Mobile web UI: the right-hand tab rail no longer overlaps the composer and bottom bar, and Stop / Queue / Pause respond on the first tap. The rail was swallowing touches over the Stop button, and pressing a button collapsed the on-screen keyboard, shifting the layout and cancelling the tap; buttons now leave the keyboard open.
