# Release Notes (Working Draft)

This file is the working draft for the next release. When a version is tagged, this file is renamed to `<version>.md` and a new empty `current.md` is created.

## Changes

- **Fix:** Preserve reasoning/thinking blocks on the Anthropic provider: thinking blocks (with signatures) are now captured, persisted in conversations, and replayed on the wire (thinking-first ordering within assistant messages), fixing HTTP 400s in Claude tool loops and satisfying Kimi/MiniMax reasoning-history requirements. New per-model config knobs `preserve_reasoning` (default true) and `display_reasoning` (default false, thinking hidden from UI). Non-Anthropic providers and knob-off models strip reasoning at capture.
- **Fix:** Orchestrator context meter in the web Session panel / TUI status bar now correctly survives save/load after delegations — it no longer shows a sub-agent's context size.
- **Fix:** Anthropic thinking-block capture seam: `create_anthropic_agent` was building the rig `Agent` via `.hook(hook.clone())` and only then patching `preserve_reasoning` onto the returned `SessionHook`. Because `SessionHook` is `Clone` and `AgentBuilder::hook` stores the value, the agent's embedded hook kept `preserve_reasoning: false` forever — silently stripping every thinking block at the capture seam even when the resolved knob was true. Extracted `build_anthropic_session_hook` so the knob is applied *before* the hook reaches the agent; the same helper is now reused by `ProviderInfo` so the two cannot diverge. 14 prior tests in `tests/scenarios/reasoning_preservation.rs` all constructed `SessionHook` directly and bypassed this seam, which is why the regression slipped through; the new `tests/scenarios/anthropic_provider_build.rs` locks the helper contract from both sides (default-resolves-true and explicit-false).
- **Web:** Opt-in rendering of Anthropic thinking blocks in the SPA. With `display_reasoning: true` on a model or provider, assistant messages now show a collapsed-by-default "Thinking" `<details>` above the prose — multiple blocks render in order, and expanded content is plain monospace text. When `display_reasoning` is off (the default) the field is stripped server-side and no DOM is emitted, so there is zero visual change for existing users. The virtualizer seed estimate folds thinking length in so expanded rows don't punch a hole in the end-anchored scroll. TUI thinking rendering remains a possible follow-up.
