# Release Notes (Working Draft)

This file is the working draft for the next release. When a version is tagged, this file is renamed to `<version>.md` and a new empty `current.md` is created.

## Changes

- **Fixed `peakbot --web` hanging with a dead port when the browser can't be opened.** On a local session the server tries to auto-open the browser; it used `open::that`, which *waits* for the spawned handler (`xdg-open`) to exit. On systems where `xdg-open` blocks (misconfigured/absent MIME handler), that stalled the async runtime **before** `axum::serve` was ever reached — the port was bound so connections were accepted into the backlog, but every request hung with 0 bytes received. Switched to the fire-and-forget `open::that_detached`, so serving starts regardless of what the browser handler does.

- **Web UI — render images referenced by the agent in markdown replies.** When the agent's reply includes `![alt](src)` for a local file (a chart it generated, a screenshot it pulled, a logo in the cwd), the SPA renders the `<img>` tag but the browser can't load a bare relative path — it needs a URL. Add a single endpoint `GET /_peakbot/file/*path` (token-gated when the server is) that resolves `<path>` against the session's cwd and streams the bytes with the right `Content-Type`. Document the URL scheme in the system prompt so the agent can emit `![screenshot](_peakbot/file/foo.png)` for any file it produces or finds in cwd; the SPA already renders `<img>`, so no frontend rendering changes are needed. Path traversal (`..`) is refused; missing files return 404. Stands alone — useful on its own before any upload UI ships.

- **Web UI — upload and download files in the working directory.** Build on the previous entry's `GET /_peakbot/file/*path` download/embed primitive and add `POST /_peakbot/upload` (multipart, writes into cwd). Composer: the existing drag-drop zone accepts any file type (was images-only) and shows a file chip per attachment; on send the path rides the message as a `[file:rel/path]` token that the agent resolves with `file_read` (mirrors the `[img:…]` token pattern in `vision.rs`). Agent replies: a small markdown post-processor rewrites bare cwd-relative paths into `[_peakbot/file/…](_peakbot/file/…)` download links so `see foo.pdf` becomes clickable without any special syntax. System prompt: tell the agent about the file-server URL prefix and that uploads land in cwd. Token-gated; upload size cap (e.g. 50 MB) and per-request count cap to keep a runaway upload from filling the disk; path traversal refused on both upload and download.
