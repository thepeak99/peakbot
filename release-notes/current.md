# Release Notes (Working Draft)

This file is the working draft for the next release. When a version is tagged, this file is renamed to `<version>.md` and a new empty `current.md` is created.

## Changes

- Added `peakbot --web` (Phase 0): the binary now embeds a React + Vite + Tailwind web UI via `rust-embed`, served on a fixed loopback port by a small axum server. The bundle is a **full static mock** of the finished UI — top bar with model/tokens/cost, welcome banner, a transcript rendering every message role (user, agent, tool call, tool result, summary, background), a side rail with session stats, a context-usage meter, todo and background-process panels, a foreground `bash` output strip, and the composer — all driven by hardcoded mock data. No WebSocket or live state yet; that is Phase 1.
- New `make web` target builds the SPA (`npm install && npm run build`) so `cargo run -- --web` shows the real UI. The four release Dockerfiles now run the same Node stage, so release binaries ship the real bundle too.
- `build.rs` writes a self-explaining stub `web/dist/index.html` when `make web` hasn't been run, so a node-free `cargo build` still produces a working binary that tells the operator what to do. CI installs Node 22 and runs the real frontend gate (`npm ci && lint && typecheck && build`, where `lint` is ESLint) before the Rust checks.
- `peakbot --web` (Phase 1): the web UI is now **live**. A `GET /ws` WebSocket endpoint drives a fresh, independent agent session per browser connection — each tab is its own transcript, todo, stats, and context; closing it tears the session down (including any background PTY children). The frontend connects over WebSocket, renders live `AppState`, sends messages, streams the "working…" spinner and Stop button, and answers `/help`, `/stats`, and other slash commands. Agent replies, compaction summaries, and tool results render as GitHub-flavoured Markdown (react-markdown + remark-gfm) with syntax-highlighted code (rehype-highlight); user input and system lines stay literal, and no raw HTML is rendered.
- Introduced a **session factory** (`create_session`) shared by every View: the TUI and stdio Views build one session; the web UI builds one per connection. The stdio/web wire protocol was extracted into a single shared `src/ui/wire.rs` so both transports change together. No new backend routes or `UiAction` variants — the web UI is a render of the existing `AppState` plus the existing inbound actions.
- `peakbot --web` (Phase 2): commands, models, and conversations are now interactive. A **model switcher** dropdown in the top bar lists the model registry and switches with one click; a **conversations picker** in the side rail lists saved conversations (numbered, by title) and loads one on click — both confirm first when they would clear a non-empty transcript. The composer gained a **slash-command palette**: type `/` to filter commands (↑/↓ + Enter/Tab to pick, Esc to dismiss). Session stats and the context-usage meter were already live from Phase 1. The command list is served by a new read-only `GET /commands` endpoint sourced from `builtin_commands()` (the single source of truth — no duplicated list, no WebSocket-protocol change).
- The web conversations picker now shows a spinner + "Loading conversations…" while the async list is in flight, instead of flashing "No saved conversations." before the data lands.
- Fixed the web UI welcome banner going stale after a `/model` switch: it now updates the provider, model, and max-tokens shown to match the model just switched to (previously it kept displaying the boot model even though the model selector and status bar had already changed). The TUI's static banner is unaffected.
