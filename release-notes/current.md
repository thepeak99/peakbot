# Release Notes (Working Draft)

This file is the working draft for the next release. When a version is tagged, this file is renamed to `<version>.md` and a new empty `current.md` is created.

## Changes
- Added config **profiles**: a named, boot-selected overlay (`profiles:` in the master config) that replaces `tools:` and/or `memory:` wholesale for a deployment. Select one with `--profile <name>`; it is applied last (after per-repo merge) and re-applied on every reload, so it survives `/cd`, `/model`, `/new`, `/load`, and `/pipeline` — a profile that disables `bash` stays disabled even if a repo you `/cd` into tries to re-enable it. Profiles are master-config only; a `profiles:` block in a per-repo `.peakbot/config.yaml` is ignored with a boot warning. See the **Profiles** section of `README.md`.
- Added a **`pipelines:` gate to profiles**: a profile can now cap which pipelines (multi-agent teams) are available, using the same filter as `tools:` and `skills:` — an `only` allowlist, a `disabled` blocklist, or `enabled: false` for none. The gate names pipelines from the master config's `pipelines:` list (an unknown name is a boot error listing the known ones) and is applied after the per-repo merge, so it is a ceiling a checked-out repo cannot void: `enabled: false` runs single-agent even if a repo declares its own pipelines. When a profile is active, boot prints what it overrides, e.g. `ℹ profile 'web' active — overrides: tools, memory, pipelines.`
- `tools:` now accepts **`enabled: false`** for "no built-in tools" (previously the only way was listing every tool in `disabled:`). `tools:`, a role's `skills:`, and a profile's `pipelines:` now share one filter with one meaning: an empty `only:` (or no filter at all) means no filtering — everything is allowed — while `enabled: false` means nothing is allowed. Existing `tools:` and `skills:` configs behave exactly as before.
- Added a **`system_prompt:`** key (top level or inside a profile) that supplies the **entire static head** of the system prompt — it replaces the built-in persona *and* the built-in tool guidance, while everything dynamic (memory, skills, the environment block, `agents.md`, and a pipeline's `# Orchestrator Instructions`) still follows it. The built-in core guidance is roughly 69% tool-specific coaching (a `bash` section, "prefer the file-edit tools over `bash`/`sed`/`awk`", `think`, `todo`), so a deployment that disables those tools no longer has to ship advice for using tools it doesn't have. **Warning:** setting `system_prompt:` drops the built-in tool guidance entirely — if you only want a different voice, use `persona:` instead; it replaces just the persona, keeps the built-in guidance, and keeps tracking releases.
- **`persona:` and `system_prompt:` fill the same slot** and are mutually exclusive: whichever key a config source sets takes the slot and clears the other, so a per-repo `persona:` beats a master `system_prompt:` and vice versa; a profile is applied last, so its choice is a ceiling (and a `system_prompt:` likewise outranks a pipeline's own orchestrator persona). Setting both keys in one file is a config error naming the file, as is a blank/whitespace-only `system_prompt:` — remove the key to get the built-in prompt.
- Removed the **token and cost counters from the web UI top bar**: the counter block in the top right of the chat view no longer renders (and with it the `stats` prop and `SessionStats` import in `TopBar`). Token/cost tracking itself is unchanged — stats are still collected per session and still shown in the Session tab's stats panel.
- Pin the macOS cross-build image to `cargo-zigbuild:0.23.3` — the unpinned `:latest` drifted to 0.23.4, whose `-exported_symbols_list` regression (upstream #479) broke linking of all cdylib dependencies for Apple targets.
- Stopping a turn (or closing a web session) while a sub-agent is running **no longer loses the `delegate` result silently**: the orchestrator's in-flight tool call is now answered with a persisted `INTERRUPTED` result quoting the sub-agent's last message, and orphaned tool calls in older conversations reach the model as `INTERRUPTED` instead of being stripped, so "continue" no longer redoes finished side-effecting work.
- **Pause sub-agents.** While a sub-agent is running, a Pause button (web), `Ctrl+P` (TUI) or `/pause` / `/resume` lets you pause it and resume it later. The pause takes effect before its next LLM call or tool call; a step already in flight finishes first. Paused time never counts toward `delegate_secs` or tool timeouts, so you can stay paused as long as you like. Stop still aborts everything, including a paused sub-agent. Pause is for sub-agents only; Ollama sub-agents can't be paused.
- **Mobile: queue a message while the agent is working.** The composer now keeps a dispatch button (`Send` → `Queue` while running) next to Stop, so touch users can queue follow-ups mid-turn — on a phone the single action button is otherwise replaced by Stop (since Enter inserts a newline by design), leaving no way to submit. While a turn is running a hint line reads `⏳ N queued · sent when this turn ends · Stop discards them`, sourced from the pending-input count in `AppState`; the Stop button's accessible name carries that discard warning. Desktop Enter-to-send/queue is unchanged. Partially addresses #123 (criteria a, b, g) — the per-entry queue list with removal (c–f) is still open. (#123, partial)
- Web UI: raw tool output (`tool_result`, including base64 images) is no longer sent to the browser on every state update. The UI only ever displayed `content`, so nothing visible changes, but frames shrink by roughly 60–86% on tool-heavy conversations (e.g. a 1 MiB `view_image` result no longer rides along with every update).
- Mobile composer: icon-only Pause/Stop while a turn runs, labelled Queue replaces them once you type; fixes squeezed textbox and missing Stop on phones.
- Web UI: the queued-messages indicator now appears only under the composer; the duplicate top-bar badge was removed.
- Web UI (mobile): the connection indicator shows only a green dot when connected; the "connected" label is hidden below the lg breakpoint.
- **Test infra (web):** the vitest suite installs a working in-memory `localStorage`/`sessionStorage` when the runtime's global is a stub — Node ≥ 23 exposes experimental method-less versions of these globals that shadow jsdom's real Storage, which broke every `TopBar` component test on Node 25.
