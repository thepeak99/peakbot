# Release Notes (Working Draft)

This file is the working draft for the next release. When a version is tagged, this file is renamed to `<version>.md` and a new empty `current.md` is created.

## Changes

- Added a `/cd <path>` command to change PeakBot's working directory mid-session without restarting (#124). It mirrors `/model`: on a conversation with content it asks the same confirmation overlay before switching, and on an empty conversation it switches immediately. `~` expands to `$HOME`, relative paths resolve against the current directory, and the target is canonicalised and checked to exist before anything changes — a bad path errors cleanly with no side effects. Switching starts a fresh conversation (chat, todos, stats reset) and kills any `bash_bg` processes rooted in the old tree. The new directory is written into the system prompt (so tools, skills, and `agents.md` all see it), is persisted with the conversation, and is re-activated on `/load`. `/cd` with no argument prints the current directory. The working directory and the active model are independent axes — switching one preserves the other.
- The current working directory is now shown in the TUI status bar (`📁 <path>`), home-abbreviated to `~` and tail-truncated on long paths, and it updates live after `/cd`.
- Fixed the `/cd` confirmation dialog clipping long directory paths: the fixed-width modal now wraps its question and grows vertically to fit, so the full path is always visible instead of being cut off at the border (short questions are unchanged).
- Unified conversation-reset cleanup behind a single `StateManager::reset_conversation_state()` (clears chat, stats, todos, background processes, and the bash panel), now shared by `/new`, `/model`, and `/cd` so no reset path can forget a surface.
- The web UI now shows the current working directory in the top bar and lets you change it with a directory picker (#144, follow-up to #124). A cwd chip sits beside the model switcher (folder basename, full path on hover); clicking it opens a folder browser that navigates into sub-directories and back up, and a "Use this directory" action commits the choice. Committing reuses the `/cd` session-reset semantics: on a conversation with content it asks for confirmation first (mirroring the model switcher), and on an empty one it switches immediately; re-selecting the current directory is a no-op. The chip is driven purely by the state broadcast, so it stays correct after a typed `/cd`, a `/load`, or a sticky-session reconnect. Path resolution and browse errors (no such directory, permission denied) are handled entirely on the backend and surfaced inline in the picker — the browser never canonicalises paths itself. Two new protocol frames back this: `switch_cwd` (which reuses the existing `ChangeCwd` action) and a `list_dir` → `dir_listing` request/response for the browser. On narrow (mobile) viewports the folder browser now opens as a full-width panel pinned to the screen edges instead of a fixed 320px dropdown anchored to the chip, which previously overflowed the right of the screen and clipped the "Use this directory" button off-screen; desktop layout is unchanged.
- The web UI composer no longer sends on Enter on touch devices. A small `useMediaQuery("(pointer: coarse)")` hook in `Composer.tsx` detects phones, tablets, and laptops in tablet mode; on those devices Enter inserts a newline and the only path to send is the button, because the on-screen return key is one mis-press away from firing a half-typed message. On a fine-pointer device (desktop with a mouse/trackpad, or a laptop with a keyboard attached) Enter-to-send is preserved unchanged. The placeholder and the keyboard-hint line below the textarea now show "tap Send" / "Send to dispatch" on touch and the original "Enter to send" on desktop.
- The web UI now has a sidebar drawer on mobile and tablet. The right-rail aside (conversations, stats, todos, background processes) is hidden below the `lg` breakpoint (1024px) — the same breakpoint it was already hidden at — but a hamburger button now appears in the top bar to open it. Tapping the hamburger slides in a right-anchored panel with a semi-transparent backdrop; the backdrop, an explicit X button, the Escape key, and selecting a conversation all close the drawer. A `Sidebar` component holds the four panels and is rendered in two places (the static aside on `lg+`, the drawer on smaller screens); the two instances are independent because only one is ever on-screen at a time. Resizing from a small viewport to `lg+` while the drawer is open auto-closes it; while the drawer is up, the body scroll is locked to prevent iOS rubber-banding.

- Fixed a release-build regression introduced in the web UI Phase 0 PR (#135): all four Dockerfiles (linux/windows/macos/android) inserted a new `FROM node:22 AS web` stage between the rust setup and the cargo build, which split the rust build across stages 1 (`builder`) and 2 (`web`). The final `COPY --from=builder` still referenced stage 1, where no binary was produced; BuildKit then silently pruned the `web` stage because nothing referenced it, so the final COPY failed with `no such file or directory`. Reordered every Dockerfile so `web` is the first stage, `builder` (the rust toolchain stage) is the second, and the final COPY references `builder` — the stage that owns the cargo build. The dummy-main dependency cache and the `COPY --from=web /web/dist` SPA bundle import are unchanged; cache locality and image size are identical.
- Fixed a second release-build regression from the same PR (#135): `build.rs` uses `include_str!("build/stub_index.html")` (the node-free fail-safe stub), but none of the four Dockerfiles copied the `build/` directory into the build stage. Once the build script tried to compile, the include_str! pointed at a path that didn't exist in the container and the build script itself failed to compile. Added `COPY build/ build/` next to the existing `COPY build.rs ./` in every Dockerfile; same layer-cache locality as `build.rs` (only invalidates when the stub changes).
