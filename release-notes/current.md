# Release Notes (Working Draft)

This file is the working draft for the next release. When a version is tagged, this file is renamed to `<version>.md` and a new empty `current.md` is created.

## Changes

- **UI**: the `🛰 N bg` satellite indicator is now shown in the **idle** title bar (single-line and multiline input modes), not only while the agent is working. Previously `bg_segment` was computed inside the `is_running = true` arm only, so background processes were invisible during idle turns. (regression pin in `repl_impl.rs` snapshot tests)
- `bash_bg`: process **exit notifications now always reach the model**, even when the capped-tier circuit breaker is suppressing chatty output. Exits are one-shot terminal transitions that cannot loop, so the breaker has no protective value there; the suppression check now exempts exits explicitly. (regression pin in `bg_processes::tests::exit_notification_bypasses_capped_suppression`)
- `bash_bg`: rewrote the tool description and tightened the system-prompt line to teach the **event-driven contract** explicitly — the model is auto-woken on output and on exit, and must **not** `sleep N && bash_bg list` to wait. The correct pattern after `bash_bg start` is "end your turn; the next `[bg output]` turn is your cue." Also clarified that `capture_output_lines: 0` still delivers the exit notification.
- `agents.md` Tools Overview synced for `bash_bg` with the same no-poll + always-notify-on-exit guidance.
- **Shell detection**: PeakBot now auto-detects the best available shell at runtime and exposes only ONE shell tool to the model. Detection priority: `PEAKBOT_SHELL` env override → WSL → Git Bash → PowerShell 7+ (`pwsh`) → PowerShell 5.1 (`powershell`) → Unix `/bin/sh` fallback. On Windows with no shell found, a startup warning is shown but PeakBot continues (file editing and other tools still work). The detected shell is stored in `StateManager` and used by both the synchronous shell tool and `bash_bg` background processes. The `/model` rebuild path preserves the shell choice across switches.
- **Added `README.md`** — polished project readme with feature overview, quick-start guide, configuration examples, usage samples, architecture diagram, and development instructions. Co-authored by PeakBot!
- **Fixed conversation title feature (issue #40)**: three bugs were causing titles to not work correctly:
  - `/rename` now sets the `title` field (which takes display precedence in `/conversations`) rather than just the creation `name`, and persists the change to storage.
  - `/rename` now updates `updated_at` and saves the conversation — previously the rename was lost on restart.
  - Auto-generated titles now work correctly when the first turn involves tool calls. The old `msg_count != 2` short-circuit incorrectly skipped title generation whenever there were tool calls between the user message and the first assistant response. The check is now based on whether the conversation already has a title and whether there's at least one user and one assistant message. (regression pins in `state_manager::tests::{maybe_generate_title_does_not_short_circuit_on_tool_calls, maybe_generate_title_is_noop_when_title_exists, rename_conversation_sets_title_and_persists, rename_conversation_overwrites_existing_title}`)
- **Fixed slash-command autocomplete popup closing on extra space (issue #52)**: when the user typed an extra space in Argument mode (e.g., `/model  ` with two spaces), the popup would unexpectedly close. The `sync_popup()` function's `!rest.contains(char::is_whitespace)` check rejected any `rest` with whitespace — including a single trailing space from `strip_prefix("/model ")`. The fix trims leading whitespace from `rest` before the whitespace check, so `/model  ` is treated the same as `/model ` (empty prefix, popup stays open). Whitespace inside a non-empty prefix (e.g., `/model x y`) still correctly closes the popup. (regression pins in `model_popup_tests::{backspace_from_argument_mode_past_slash_keeps_popup_open, backspace_from_argument_mode_shows_model_command, double_space_in_argument_mode_should_not_close_popup, space_after_backspace_from_argument_reopens_arg_popup}` and snapshot tests `command_popup_model_prefix_after_arg_transition`, `command_popup_mode_prefix_no_matches`)
- **Fixed slash-command autocomplete popup not reopening after backspace (issue #52 follow-up)**: when the user typed `/mod`, hit space (the popup auto-closes because whitespace leaves command-name territory), then backspaced the space, the popup did not reappear — same regression in Argument mode (`/model sonn x` → backspace `x` and space → popup gone). Root cause: `sync_popup()` returned early on `popup is None`, so a "reactively-closed" popup could never restore itself. Fix: introduced a `popup_dismissed: bool` flag that distinguishes *explicit* dismissals (Esc, Tab/Enter accept, Shift/Alt+Enter — sticky, persists across buffer edits until the buffer clears) from *reactive* closes (sync_popup hiding it because of transient whitespace — non-sticky). A new `try_reopen_popup()` helper restores the popup when the buffer matches a valid command-prefix shape and no explicit dismissal is in force. (regression pins in `model_popup_tests::{backspace_after_auto_close_in_slash_mode_reopens_popup, backspace_after_auto_close_in_argument_mode_reopens_popup, esc_dismissal_persists_across_buffer_mutations, tab_accept_dismissal_persists_across_backspace}`)
- **Persist todo items with conversation (issue #4)**: todo items were session-local — saving and loading a conversation did not preserve them. They vanished on `/load`. Fix: added `todos: TodoList` with `#[serde(default)]` to the `Conversation` struct (backward-compatible with old files), wired `sync_to_conversation()` to snapshot the live todo list before save, and wired `sync_from_conversation()` to restore it on load and push it to the UI. Storing the full `TodoList` (not just `Vec<TodoItem>`) preserves `next_id`, preventing ID collisions when adding new tasks after a load. Loading a conversation with todos now auto-shows the todo panel (mirrors the existing auto-show behavior when the first task is added in a live session). (regression pins in `state_manager::tests::{todo_roundtrip_through_sync, pre_todo_persistence_conversation_loads_with_empty_todos, sync_from_conversation_with_todos_auto_shows_panel, sync_from_conversation_without_todos_keeps_panel_hidden}`)
